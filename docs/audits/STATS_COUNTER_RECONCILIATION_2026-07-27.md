# Сверка счётчиков статистики — 27.07.2026

## Единые определения

| Показатель | Что считается | Источник |
|---|---|---|
| Получатели | Уникальные строки получателей рассылки | `campaign_recipients` |
| Попытки | Каждая техническая попытка, включая повтор | `delivery_attempts` |
| Принято провайдером | Уникальный получатель с итогом `sent` или `in_chain` | `campaign_recipients.send_status` |
| Доставлено | Уникальный получатель с подтверждением доставки или более сильным событием | webhook/API-события провайдера |
| Итоговые ошибки | Уникальные получатели, у которых итоговый статус `failed` | `campaign_recipients.send_status` |
| Неудачные попытки | Все ошибки попыток, включая ошибку до последующего успешного повтора | `campaigns.error_count` / `campaign_batches.error_count` |

Неудачная отправка увеличивает только «Попытки» и «Неудачные попытки». Она не
увеличивает «Принято провайдером».

Для текущих CampaignFlow-рассылок источником числа попыток всегда служит
`delivery_attempts`. `sent_mail_log` используется как резервный источник только
для старых рассылок, у которых записей `delivery_attempts` нет. Складывать эти
источники нельзя: одна логическая попытка может создать несколько строк
`sent_mail_log`, например при отправке на основной и резервный адреса.

Проценты общей воронки кампании считаются от всех зарегистрированных попыток:
`этап / delivery_attempts × 100%`. Частные показатели сохраняют собственные
знаменатели: доставляемость — от принятых провайдером, открываемость — от
доставленных (или от принятых, если подтверждений доставки нет).

## Подтверждённые причины расхождений

1. Карточка рассылки считала успешных уникальных получателей, а колонка
   «Ошибки» рядом с ней считала ошибки попыток. После одного сбоя и успешного
   повтора интерфейс мог показать `Принято: 1`, `Ошибки: 1`. Это не две разные
   ошибки получателя: итоговая ошибка равна нулю, а неудачная попытка равна
   единице.

2. Менеджерская статистика строится из `sent_mail_log`, куда запись попадает
   после принятия письма провайдером, и группирует данные по компании/строке.
   Операционная карточка строится по `campaign_recipients`. Если у одной компании
   несколько строк-получателей, менеджерский экран может показать одну компанию,
   а карточка рассылки — несколько получателей.

3. «Доставлено» известно только после события провайдера. Сразу после успешного
   вызова API возможна нормальная последовательность: `Принято провайдером: 100`,
   `Доставлено: 0`, `Ожидают статуса: 100`. Для SMTP без DSN нельзя достоверно
   получить финальную доставку; принятие SMTP-сервером не следует подписывать как
   подтверждённую доставку.

## Примеры для ручной сверки

- Один адрес: первая попытка `failed`, вторая `sent`:
  `Получатели=1`, `Попытки=2`, `Принято провайдером=1`,
  `Итоговые ошибки=0`, `Неудачные попытки=1`.
- Две строки одной компании, оба письма приняты:
  операционный экран показывает `Получатели=2`, менеджерская агрегация по
  компании может показывать `Компаний=1`.
- Сто писем приняты API, webhook ещё не пришёл:
  `Принято провайдером=100`, `Доставлено=0`, `Ожидают статуса=100`.
