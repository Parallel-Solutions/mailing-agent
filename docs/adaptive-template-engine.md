# Адаптивные шаблоны КП

Движок применяется только к коммерческим предложениям. Договоры продолжают формироваться из DOCX прежним способом.

## Пользовательский сценарий

Пользователю не нужно добавлять служебные поля. Сначала загружается таблица данных, затем обычный шаблон КП в DOCX или PDF. Сервис сопоставляет значения первой строки таблицы с текстом примера в шаблоне, распознаёт номер, дату, адресата и территорию, после чего сохраняет исходник и создаёт внутреннюю размеченную версию.

Перед активацией worker автоматически формирует короткий, обычный и стрессовый варианты. Новая версия становится активной только если все варианты остались одностраничными, значения действительно присутствуют в PDF и не осталось незаменённых маркеров. Предыдущая рабочая версия при ошибке сохраняется активной.

Автоматический режим рассчитан на DOCX и одностраничные PDF с текстовым слоем. Обычный PDF без служебных полей компилируется во внутренний семантический HTML: текст восстанавливается как цельные абзацы и таблицы, а логотип, печать и декоративные элементы становятся встроенными ресурсами. Сканированный PDF без распознаваемого текста пока отклоняется: для него нужен отдельный OCR-этап и обязательная визуальная проверка. Существующие шаблоны с явными полями также поддерживаются и обрабатываются без повторного распознавания.

## Протокол полей

В DOCX и HTML переменные отмечаются как `{{FIELD_NAME}}`. Имя состоит из латинских заглавных букв, цифр и `_`, начинается с буквы. Маркер может быть разбит Word на несколько runs — движок всё равно его найдёт и сохранит оформление первого run.

Пример:

```text
Исх. № {{OUTGOING_NUMBER}} от {{DATE}}
{{ADM_NAME}}
{{HEAD_GREETING}}
```

PDF с именованными AcroForm-полями (`FIELD_NAME` или `{{FIELD_NAME}}`) заполняется напрямую, с подбором размера текста и последующим flatten. Обычный PDF с текстовым слоем не требует от пользователя никаких полей: движок находит значения примера, восстанавливает смысловую HTML-разметку и помещает переменные внутрь исходного текстового потока с наследованием шрифта, цвета, жирности и межстрочного интервала. Поэтому длинная фраза переносится целиком, а не отдельными наложенными блоками. Скан без текстового слоя и без формы отклоняется.

HTML не может содержать JavaScript, обработчики событий и внешние HTTP/file-ресурсы. Изображения и шрифты следует встраивать как `data:` URI.

## Жизненный цикл

1. Загруженный файл компилируется в неизменяемую версию в `templates/.adaptive/kp/versions/`.
2. Worker формирует три PDF: с короткими, обычными и стрессовыми значениями.
3. Для DOCX и HTML движок уменьшает только переменный текст/масштаб страницы от `100%` до `70%`.
4. Все три результата должны иметь ровно одну страницу и не содержать незаменённых маркеров.
5. Успешная версия атомарно становится активной. Неуспешная остаётся в истории с отчётом, а предыдущая активная версия продолжает работать.

Статус версий доступен через `GET /api/templates/adaptive/status`. Ручная активация уже сертифицированной версии — `POST /api/templates/adaptive/{template_id}/activate`.

## Включение

```env
KP_ADAPTIVE_TEMPLATE_ENGINE=1
```

При выключенном флаге или отсутствии активной версии используется прежний генератор КП. Контекст проходит существующую нормализацию склонений до рендера, а готовые документы — существующую проверку филолога после рендера.
